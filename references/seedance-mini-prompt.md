# Seedance 2.0 Mini 提示词规范

> **模型快照**：编写时使用 `doubao-seedance-2-0-mini-260615`，成本、服务档、时长、分辨率与比例会随平台和账号变化；执行时以用户当前 UI/API 为准，并在成本表记录实际参数。
> **单次时长**：按用户当前平台允许的单次时长，用时间戳覆盖本次计划段长，超长连续叙事再走第六节「视频延长」。但 Phase 7.5 标为 P2/P3 的产品镜不受“写满最大时长”约束：P2 应独立 1-3 秒并重新注入真实产品参考；P3 必须走真实产品资产微动/合成，不用 Mini 重画包装。
> **规则来源**：本文件规则来自 SkillHub `@user_c246cf13/rong-shu-seedance-mini-video-creation`（Seedance 2.0 Mini 官方 SKILL）及即梦官方 prompt 示例，2026-08 吸收。

## ⚠️ 最坑的一点：不要套用 2.0/2.5 的六板块

Seedance 2.0/2.5 走「六板块 + @图片N」的**结构化长提示词**（见 `seedance-prompt.md`）。**Mini 不吃这套**——它的提示词是**一句话式简洁公式**，塞六板块标题反而会干扰生成、浪费生成次数。

**Mini 的核心公式（官方推荐）**：

```
提示词 = 主体 + 运动，背景 + 运动，镜头 + 运动
```

- **具象描述**，杜绝抽象词（❌"美丽的" → ✅"穿白裙的女孩站在樱花树下"）。
- **重要内容前置**，不重要的一律省略。
- **描述场景与变化，不是静止瞬间**：写清这几秒里发生了什么。

## 一、提示词模板

### 电商产品视频（本 SKILL 主场景）

```
@图片1 作为产品主视觉
[产品名称] 在 [场景] 中，[核心卖点动作]，镜头 [运镜方式]，[光线/氛围]，[品牌质感]
```

### 营销/口播短视频（有台词时）

Mini 仍然使用一句话与时间戳，不使用六板块；但有口播时，每个发声节拍必须在对应时间轴内写清“说话人 + 原话 + 语言 + 口型/声音”。台词只能复制确认剧本的原话，不能写成“自然讲解”“对镜说话”。

```text
@图片1 仅作为[人物身份/产品外观/首帧]参考。0-4秒：[角色A]看向镜头，做出[一个核心动作]，用中文说：“[剧本原话]”，口型与该句同步，镜头[一个运镜]；4-8秒：[角色A]继续说：“[剧本原话]”，[一个动作变化]，镜头[一个运镜]；8-15秒：[角色A]说：“[剧本原话]”，[收尾动作]。真实摄影质感、自然光影、清晰人声，不把台词显示为画面字幕。
```

- 单句以 1.5-2.5 秒能说完为准；超过承载时长只能按自然停顿拆到相邻时间段，原话不得删改。
- 画外音写“画外音用中文说：‘[原话]’，画面内人物双唇保持闭合”。
- 无对白时必须在该节拍写“无对白，仅[环境音/动作音]”。

### 通用快速生成

```text
[主体] 在 [环境] 中，[一个动作/变化]，[一个镜头语言]，[具体光线、材质与真实摄影质感]
```

> 人物视频默认写实真人：真实皮肤纹理、真实服装材质、自然光影和可信物理反馈。黑白素描只用于人物资产图审核，不能成为最终视频风格。`3D 渲染产品展示`仅用于已确认的 13 动画/3D 演示路线，不得用于真人镜头。

## 二、@引用规则（和 2.0/2.5 一样，但更依赖首帧图）

- 命名：`@图片1`~`@图片9`、`@视频1`~`@视频3`、`@音频1`~`@音频3`（必须中文命名，不是 `@image1`）。
- **每个 @ 必须标清用途**：`@图片1为首帧`、`参考@视频1的运镜`、`音效参考@音频1`。
- 区分「参考」与「编辑」。
- **图生视频优先**：文生视频随机性大，建议先用图片生成模型造好首帧，再图生视频；上传图片要**高清高质量**，图片质量直接决定视频效果。

## 三、时间戳分镜（一个 PROMPT 覆盖本次计划段长）

一个 PROMPT 覆盖用户当前平台允许且 Phase 7.5 计划的完整叙事段长，时间戳连续无空洞；编写时常见 15s 示例（不要机械拆成 5 秒一段）：

```
0-3秒：[画面描述 + 镜头语言]
3-8秒：[画面描述 + 镜头语言]
8-12秒：[画面描述 + 镜头语言]
12-15秒：[画面描述 + 镜头语言]
```

## 四、技术参数前缀（可选，写开头）

提示词开头写画幅/帧率/时长/色调总纲：

```
2.35:1，24fps，15秒，霓虹高饱和冷暖对比
```

## 五、禁止项声明（结尾写）

```
禁止：模型随机生成额外文字、字幕、LOGO 或水印；P3 已确认真实包装由真实资产/合成链路保留
```

## 六、视频延长 / 多段（超过当前单次时长时）

Mini 单段先覆盖当前允许的完整段长；只有连续叙事超过当前单次时长，才按当前平台能力使用「视频延长」链式续写。下例以 15s 为快照：

```
将@视频1延长15秒。1-5秒：[接上段结尾画面 + 动作]；6-10秒：[……]；11-15秒：[……]
```

- 每段写清**衔接点**：上段结尾画面 = 下段开头。
- 分段逻辑：16–30s 拆 2 段、31–45s 拆 3 段、46–60s 拆 4 段、>60s 多段 + 剪辑拼接。
- 与 2.0 的「尾帧高清重绘衔接」不同，Mini 优先用「视频延长」链式续写直接衔接——但**仅在分镜（Phase 7）标记「尾帧衔接 = 是」的连续段**才走；跳切段（分镜标「否」）直接新景别独立生成，不取尾帧。视频延长本身是平台内高清续写，**不允许在衔接处用低清尾帧糊弄**（不存在"画质略低就免还原"的退路）。

## 七、电商广告场景策略

- **产品展示**：真实 SKU 的 P2 镜仅做受控小幅动作并逐镜重注入参考，P3 走真实资产/合成；360° 旋转、爆炸分解、3D 渲染只用于用户明确确认的概念/动画路线，不用于真实包装保真镜。
- **运镜选词**：环绕拍摄、推镜头、焦点转移、微距（静物特写 → 缓推/浅景深/微距）。
- **慢动作（升格）**：继承 2.0 能力，提示词写 `慢动作` / `慢镜头`；`@参考视频` 可作节奏迁移（上传节奏参考视频，标注 `@视频1 仅用于定义运镜和节奏`）。用于静物细节展示（手表/珠宝/美食特写）。
- **音效**：音效先行（画面未到声音先到）、ASMR 质感适合美妆/美食。

示例（官方真实可用）：

```
图1中的可口可乐饮料，360度高速旋转2圈后，突然停住蓄力分裂成了3个部分进行展示。随后分解后的可口可乐饮料罐的上中下三部分快速向内旋转合成，一罐完整的可口可乐饮料，3D渲染产品展示特效
```

## 八、Mini 的坑（务必避开，每条都浪费生成次数）

1. **不要套六板块**：Mini 用一句话公式，不是 2.0/2.5 的 `## 角色+参考图` 那套结构化标题。
2. **不要抽象词**：写具象动作和画面，别写"高级感、有质感"这类空词。
3. **不要只描述静止一帧**：要写"这几秒里发生了什么变化"。
4. **不要漏 @ 用途**：上传了图就必须标注每张图用来干嘛。
5. **不要塞多个动作打架**：一拍只给一个清晰运镜。
6. **文生视频能不用就不用**：先造首帧再图生视频，稳定性高得多。

## 8.5 表演降级 + 单运镜词（一句话公式，写不了复杂表演）

Mini 是一句话公式（主体+运动，背景+运动，镜头+运动），**六维物理表演砍到 1-2 个核心物理细节**（详见 `model-specs.md`「导演思维公式」），不堆砌：

- 情绪禁抽象词，但只写 1-2 个最关键的可见动作，如「指尖收紧」「脚步半停」「抬手悬空」，不写完整六维。
- 一句话里嵌 1 个运镜词即可（环绕/推近/微距/焦点转移），不按景别分级堆砌。
- 重要内容前置，抽象词一律删（❌「美丽的」→ ✅「穿白裙的女孩站在樱花树下」）。

## 九、API 参数（生成模式接入时用）

- 本 SKILL **未附带**火山引擎官方 Ark Python 适配器；如直连官方 API，调用方须按当前官方文档自行接入并使用其要求的凭证，不得假设仓库里另有官方脚本。
- 若用户的中转接口已验证兼容本 SKILL 的通用请求/响应结构，可用根目录 `video_api.cjs`，配置 `VIDEO_API_BASE`、`VIDEO_API_KEY`、`VIDEO_MODEL`，并用 `--model` 传当前实际 model id。
- 生成前先做低成本接口探测，确认 model id、时长、比例、分辨率和服务档确实受支持；探测失败就退回纯提示词模式，不自动付费重试。
