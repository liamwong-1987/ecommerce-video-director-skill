# 阶段交付核验清单（硬门）

> **用途**：防止“进入了 Phase 但没有真正交付”的假完成。每完成 Phase 4、7、8、10，必须暂停，按本文件逐项输出核验报告。任何阻断项缺失、没有可核验证据或未满足需要的用户确认，均不得进入下一阶段。
>
> **证据原则**：文字交付物须给出所在表格/章节；图片或文件须给出图号、资产 ID 或文件路径；用户确认须引用明确确认结果。不得用“已完成”“已生成”“完整”等空话代替证据。
>
> **模式差异**：纯提示词模式的“生成证据”可由完整可执行的 SPEC/PROMPT 替代，但必须明确标记“待用户生成”；生成模式必须提供真实生成文件/图片证据。凡规则要求用户确认的项目，两种模式都不得自行视为确认。

---

## 通用输出格式（每次硬门必用）

```markdown
### Phase X 交付核验报告

| 交付物 | 是否阻断 | 状态 | 证据 | 缺失/豁免理由 | 回退动作 |
|---|---:|---|---|---|---|
| … | 是/否 | PASS / FAIL / 豁免 | 图号、资产 ID、文件路径、表格章节或用户确认 | 无 / 具体理由 | 无 / 回到 Phase N 补齐 |

结论：PASS / FAIL
下一步：仅当全部阻断项 PASS 后，进入 Phase N；否则先执行列出的回退动作。
```

- `PASS`：交付物存在、内容符合本技能规则、证据可查。
- `FAIL`：缺失、内容不合格、证据不可查、或用户确认尚未取得。
- `豁免`：仅限本表明确允许的条件项；必须写出镜号/资产 ID 和具体理由。不能以“感觉不需要”豁免。

## Phase 4：纯文字剧本确认门

| 交付物 | 是否阻断 | PASS 证据与判定 | 失败时回退 |
|---|---:|---|---|
| 纯文字剧本 | 是 | 已输出完整剧本，含钩子、发展、卖点/高潮、CTA；不含分镜表、资产图或视频 PROMPT | 回 Phase 4 补写 |
| 台词/口播与说话人 | 是 | 每句台词有角色 ID 或旁白标记；无对白镜明确写“无对白” | 回 Phase 4 补全 |
| 剧本事实源一致性 | 是 | 产品卖点、平台、时长、类型、风格、合规边界均与 Phase 0-3 已确认信息一致 | 回对应前置 Phase 澄清后重写 |
| Phase 5/6 合规检查 | 是 | 合规清单已逐项核验，敏感/虚假/导流/极限词已处理 | 回 Phase 5/6 修正 |
| 用户剧本确认 | 是 | 已获得用户对纯文字剧本的明确确认 | 暂停等待确认；不得进入 Phase 7 |

**通过后**：进入 Phase 7。

---

## Phase 7：分镜与九宫格确认门

| 交付物 | 是否阻断 | PASS 证据与判定 | 失败时回退 |
|---|---:|---|---|
| 逐镜分镜表 | 是 | 每镜含镜号、时间、画面/景别、动作、台词、声音、连续性、运动速度、资产需求、尾帧衔接；含产品视频另有 P0-P3 与 P2/P3 交互风险 | 回 Phase 7 补表 |
| 9 宫格分镜图 | 是 | 生成模式：已有整张 3×3 图片文件/图号；纯提示词模式：已有完整 3×3 分镜图生成 SPEC，并标记待用户生成。15 秒 1 张、30 秒 2 张、后续每 15 秒追加 1 张 | 回 Phase 7 重做整张宫格；禁止用文字表替代 |
| 逐格台账 | 是 | 每格有时间、景别与构图、人物动作、产品状态与朝向、镜头运动、P0-P3、连续性 | 回 Phase 7 补齐 |
| P2/P3 高清关键帧 | 条件阻断 | 只要出现 P2/P3 格，全部对应镜头均已有 `KF-N` 关键帧或完整关键帧 SPEC；无 P2/P3 时写“豁免：全片无 P2/P3，镜号清单为……” | 回 Phase 7 补关键帧 |
| 分镜图与台账一致 | 是 | 逐格核验无串格、串景、时间码错、产品级别错配；P2/P3 与真实资产路线一致 | 回 Phase 7 修图/台账 |
| 用户确认 | 是 | 用户已确认九宫格与逐格台账 | 暂停等待确认；不得进入 Phase 7.5/8/10 |

**通过后**：进入 Phase 7.5，完成逐镜生产路由后才可进入 Phase 8。

## Phase 8：资产完整性确认门

| 交付物 | 是否阻断 | PASS 证据与判定 | 失败时回退 |
|---|---:|---|---|
| 资产总台账 | 是 | 已列明每项 `asset_id / 类型 / 对应镜号 / 触发原因 / 生成或SPEC状态 / 用户确认状态 / 豁免理由`；并汇总计划数、已生成数、已确认数、待补数 | 回 Phase 8 建账 |
| 逐镜产品资产审计总表 | 是 | 已逐镜列 `镜号 / P级 / 路由等级 / 最低资产标准 / 实际资产ID或参考 / 状态 / 用户确认 / 豁免或回退动作`；P1/P2/P3 无一镜以空白、概念图或“后续补”通过 | 回 Phase 8 补表并补资产 |
| P-CORE 产品四视图 | 条件阻断 | 含产品 P1/P2/P3 镜时必须有客户实拍参考驱动的 1×4 单图或对应完整 SPEC；全片 P0 时可豁免 | 回 Phase 8 补 P-CORE |
| P-HERO | 条件阻断 | 每个 P2 产品动作镜均已关联场景匹配的 `P-HERO` 或同一真实产品参考，并可逐镜重新注入；无 P2 时豁免 | 回 Phase 8 补对应 P-HERO |
| P-PACKSHOT | 条件阻断 | 每个 P3 SKU 信息镜均已关联客户确认的 `P-PACKSHOT` 实拍/透明 PNG/合成方案；P3 同镜含产品动作时还必须关联 `P-HERO`；无 P3 时豁免 | 回 Phase 8 补 P-PACKSHOT / P-HERO |
| 人物资产或可灵 I2V 参考 | 条件阻断 | 有真人/角色出镜：Seedance/H3 路线具有人物黑白素描三视图；可灵路线具有用户授权的真人照片/视频 I2V 参考；无人物/角色出镜时豁免 | 回 Phase 8 补人物资产/授权参考 |
| 场景锚点 | 条件阻断 | 每个独立地点 / 室内外切换 / 空间逻辑变化均有 `SCENE-N` 资产或完整 SPEC；抽象背景或同一连续空间豁免时，写明镜号并引用资产触发矩阵条件 | 回 Phase 8 补场景资产 |
| 道具与首尾帧 | 条件阻断 | 被拿起、操作、触发卖点或剧情转折的道具均有 `PROP-N`；首帧/尾帧按资产触发矩阵和 Phase 7“尾帧衔接”判定配齐；未触发项逐项写明镜号和理由 | 回 Phase 8 补资产 |
| P2/P3 关键帧资产 | 条件阻断 | 每个 P2/P3 镜均有 `KF-N`，并关联 P-HERO/P-PACKSHOT 与对应镜号 | 回 Phase 7/8 补齐 |
| 用户确认 | 是 | 生成模式：用户已确认真实资产及资产完整性；纯提示词模式：用户已确认资产 SPEC/生成清单，或明确接受待自行生成状态 | 暂停等待确认；不得进入 Phase 9/10 |

**通过后**：进入 Phase 9 资产—路由复核；复核 PASS 后才可进入 Phase 9.5 / 10。

## Phase 10：逐镜 PROMPT 交付门

| 交付物 | 是否阻断 | PASS 证据与判定 | 失败时回退 |
|---|---:|---|---|
| 逐镜 PROMPT 全覆盖 | 是 | PROMPT 数量与 Phase 7.5 路由表镜头一一对应，无缺镜、无多镜、无未路由镜 | 回 Phase 10 补写或回 Phase 7.5 补路由 |
| 模型格式匹配 | 是 | Seedance 六板块、Mini 一句话、H3 英文字段、可灵时间轴标签各自独立，不混用 | 回 Phase 10 重写 |
| 剧本台词逐字一致 | 是 | 对白/旁白与 Phase 4 已确认剧本逐字核对；无对白镜明确写无对白 | 回 Phase 4 或 10 修正 |
| 资产引用与产品路由 | 是 | P1 引 P-CORE；P2 逐镜引 P-HERO/真实参考；P3 走 P-PACKSHOT/实拍/合成；引用用途均写“仅定义……” | 回 Phase 8 或 10 补齐 |
| 声音字段 | 是 | 有环境音/动作音效与对白/旁白；默认不写 BGM；无对白镜明确标记 | 回 Phase 10 补齐 |
| Prompt Delivery Contract FAIL 门 | 是 | 已按 `prompt-delivery-contract.md` 完成事实卡与最终验收，且无 FAIL | 回对应 Phase 修复 |
| Phase 10.5 验算报告 | 是 | 已输出逐镜时长、对白/价格落地、产品一致性、模型格式等验算过程与结论 | 回 Phase 10/7.5/8 修复 |

**通过后**：允许交付 PROMPT；生成模式仍须经过 Phase 9.5 的成本预估与用户出片审批，才可调用生成能力。
