# 资产制备工作流

> **执行方说明（重要）**：本文件里的「图片生成提示词结构 / 资产SPEC」是**交付物**，不是 agent 自动执行的指令。
> - **纯提示词模式**（默认）：agent 只把这些提示词与 SPEC 交给用户，由用户去即梦/Seedance/MiniMax/GPT-Image 等平台手动生成资产。
> - **生成模式**：仅当用户已接生图能力时，agent 才实际调用生成并把文件存到下方目录。
> 严禁在纯提示词模式下指挥 agent 调用 imagegen / 生图动作。

资产数量由已确认视频创意蓝图与分镜脚本逐镜盘点决定，脚本里出现几个就做几个，不套固定默认值。只生成实际镜头和目标模型需要的资产，避免超过模型素材预算。

## 批次授权与确认（禁止逐张打断）

生成模式默认使用三批授权：

1. **基础资产包**：真实产品主资产、人物身份资产、用户提供的真实场景资料；用于建立后续分镜事实源。
2. **分镜预览包**：每条视频完整九宫格/分镜板与逐格台账。
3. **派生资产包**：经分镜和逐镜路由触发的场景锚点、关键帧、首尾帧、P-HERO、特殊产品视角和道具。

每批开始前一次性列明：`批次ID / creative_blueprint_id与version / 资产清单与数量 / 模型或工具 / 预计成本 / 单项重试上限 / 自动回炉条件 / 停止条件`。用户确认整批后，批内不得每生成一张再询问一次。

- 在已批准数量、模型、预算和重试上限内，结构错误、穿模、产品身份错误、手部错误、比例错误或画面不符合台账时只回炉对应资产；无需重新取得逐张授权。
- 只有超预算、增加数量、更换模型/供应商、缺少真实产品或人物授权、改变已确认蓝图/产品身份、或达到重试上限仍失败时暂停。
- 纯提示词模式按同样三批组织 SPEC/PROMPT，但不调用生成；用户确认的是整批规格和待生成清单，不是假装确认不存在的图片。
- 用户明确要求精细模式时才可逐张确认；默认批次模式不能退化成逐图弹窗。

## 资产盘点规则（按脚本，不套默认值）

Phase 8 从分镜脚本逐镜盘点，脚本需要什么就列什么，数量等于脚本实际出现的次数。**不得仅凭“看起来不需要”跳过资产**：每一项均须按下方「资产触发矩阵」判定为“必出”或“豁免”，豁免必须在资产总台账写明关联镜号与具体理由。

### 资产触发矩阵（逐镜机械判定）

| 资产类型 | 必出触发条件 | 允许豁免条件 | 台账证据要求 |
|---|---|---|---|
| `P-CORE` 产品四视图 | 任一镜为 P1/P2/P3，即产品可见或可辨识 | 全片均为 P0、产品从不出现 | SKU、关联镜号、真实来源、确认状态；豁免需列全片 P0 镜号 |
| `P-HERO` | 每个 P2 产品动作/近景展示/卖点镜 | 无 P2 镜；同场景同构图且同一真实产品参考已被该镜重新注入时可复用，但须列出复用来源 | `P-HERO` ID、关联 P2 镜号、场景、允许动作 |
| `P-PACKSHOT` | 任一 P3 镜要求 Logo、包装文字、型号、价格或固定版式 | 无 P3 镜 | `P-PACKSHOT` ID、关联 P3 镜号、真实来源、文字/Logo/版式确认状态 |
| `P-TOP` | 镜头出现开罐、开盖、顶部结构、易拉环或开合状态特写 | 无上述镜头 | `P-TOP` ID、触发镜号、结构状态；豁免镜号清单 |
| `P-SIDE` | 镜头出现侧拿、手持侧面、倒酒/倾倒或侧面图形可见 | 无上述镜头 | `P-SIDE` ID、触发镜号、可见面；豁免镜号清单 |
| 人物三视图 / 可灵 I2V 参考 | 有可辨识真人或虚构角色出镜、说话、表演或需跨镜保持同一人物 | 全片无人；只出现不可辨识手部且不承担角色身份时可豁免人物三视图 | Seedance/H3：`CHAR-N` 素描图；可灵：授权真人参考 ID 与授权确认；豁免列镜号和原因 |
| 角色服装设定 | 同一可辨识角色有服装可见，或发生换装 | 全片无人、仅不可辨识手部、或服装完全不可见 | `OUTFIT-N`、角色 ID、关联镜号、服装状态；换装须标变化秒数 |
| 场景锚点 | 出现独立地点、明显室内外切换、时间/光线导致空间逻辑变化，或镜头需跨镜保持同一空间布局，且已确认分镜/真实场景不足以直接约束目标模型 | 全片纯色/抽象背景；已有用户真实场景或已确认分镜格足以直接作为视频参考；所有镜头只用同一已确认场景且无空间变化时仅 1 张 | `SCENE-N`、蓝图版本、来源分镜/真实场景、产品/人物资产、关联镜号、入口/窗户/主光/产品位；豁免列镜号和现有来源 |
| 关键道具 | 道具被拿起、操作、触发卖点、承担剧情转折，或需跨镜保持外观/状态 | 只作为远景不可辨识背景、一次性无互动且不影响剧情/卖点 | `PROP-N`、关联镜号、用途、状态；豁免列镜号和原因 |
| 首帧 | 需图生视频、人物/产品/复杂构图一致性，或该镜是连续段起点 | 纯文生且不要求接续、不含人物/产品/复杂构图 | `KF-N` 或首帧 ID、关联镜号、用途；豁免列模型与原因 |
| 尾帧 | Phase 7 台账标记“尾帧衔接=是”，或下一镜需要续写/保持构图、人物、产品状态 | 台账标记“尾帧衔接=否”且为跳切/新场景/新主体 | 尾帧 ID、前后镜号、连续字段；豁免引用 Phase 7 判定 |
| `KF-N` 高清关键帧 | 目标模型需要首帧/尾帧；动作/结构复杂；产品安装、开合、内部结构或接触容易出错；P2/P3 产品保真风险高；九宫格分辨率不足；跨镜需严格连续 | 目标模型可直接引用清晰分镜格+真实产品资产；镜头动作简单且无严格接续；纯提示词用户明确只要视频 PROMPT | `KF-N`、触发原因、镜号、来源分镜格、关联 P-HERO/P-PACKSHOT、确认状态；豁免必须写模型和现有参考 |

**判定顺序**：先逐镜读 Phase 7 台账 → 应用本矩阵 → 建资产总台账 → 再写/生成资产 SPEC。禁止反过来先随意生成几张图，再声称资产已经完整。

| 类型 | 数量依据 | 用途 |
|------|---------|------|
| 产品四视图（**1×4 拼接单图**） | 每 SKU 1 张 | 锁定产品外观（正/背/侧/顶四角度并排），跨视频共用 |
| 人物黑白素描三视图（**1×3 拼接单图**） | 每个出镜角色 1 张 | 锁定角色的外观结构、发型、服装与姿态参考（正/侧/背三角度并排），跨视频共用（可灵路径除外：选定可灵即免产素描，直接以授权真人照片/视频作 I2V 参考） |
| 角色服装设定 | **角色数 × 本条视频实际服装状态数**；同一角色同一服装状态可跨镜复用 | 锁定「穿什么」；换装才新增，不按场景机械重复生成；人物资产（非可灵路径）仍必须保持黑白素描呈现 |
| 场景锚点 | 每个独立地点 / 室内外切换 / 空间逻辑变化各 1 张；同一连续空间可复用同 1 张 | 锁定空间、光线、关键物位置；抽象背景须在台账写豁免理由 |
| 关键道具 | 被拿起、操作、触发卖点或承担剧情转折的道具各 1 个资产 | 锁定道具外观与状态；仅远景背景且不影响剧情/卖点时可豁免 |
| 首尾帧 | 首帧：图生、一致性或复杂构图镜必备；尾帧：Phase 7 标“尾帧衔接=是”时必备 | 固定构图或跨镜衔接时使用；每项豁免必须引用镜号与 Phase 7 判定 |
| P-HERO 场景化产品首帧 | 每个 P2 产品动作镜 1 张（可同场景复用，不跨场景硬套） | 真实产品进入目标场景后的图生视频起点 |
| P-PACKSHOT SKU 保真图 | 每 SKU 1 张或按正/侧面补充 | P3 信息镜、结尾定格、合成，包装文字/Logo/版式保真 |
| P-TOP / P-SIDE | P-TOP：出现开罐/开盖/顶部结构；P-SIDE：出现侧拿/手持侧面/倒酒或侧面图形可见 | 锁定罐顶/开合结构与侧面可见面；未触发时须列镜号与豁免理由 |
| SB-15 / SB-30-A/B | 15 秒 1 张；30 秒 2 张 | 9 宫格分镜预演图，锁定时间节拍、构图、产品位置与动作顺序 |
| KF-N | 按目标模型、动作复杂度、产品保真和连续性风险触发 | 从宫格和真实资产派生的高清关键帧；简单镜头可直接引用分镜格+产品资产并登记豁免 |

## 9 宫格分镜图与高清关键帧

### 宫格数量规则

- 15 秒：`SB-15`，1 张 9 宫格，9 格按时间顺序排列，每格约 1.5-2 秒。
- 30 秒：`SB-30-A`（0-15 秒）+ `SB-30-B`（15-30 秒），两张均为 9 宫格。
- 超过 30 秒：每 15 秒增加 1 张 9 宫格；最后一段不足 15 秒按实际时长分格。
- **所有视频无条件必须制作宫格分镜图**：产品视频、人物口播、剧情、品牌片、纯氛围、动画/3D、无产品视频都不能跳过。这里不是“默认必做”，而是硬性必交付。

### 每格文字台账（宫格图单独存在不算完成）

每格必须记录：

```text
格号 / 时间范围 / 景别与构图 / 人物动作 / 产品状态与朝向 /
镜头运动 / 产品可见级别 P0-P3 / 与前后格连续性 / 关键资产 ID
```

### 分镜图和关键帧的生成、确认、使用

> **分镜图硬门（所有视频适用）**：所有视频必须先交付至少 1 张整张 3×3 宫格分镜图；超过 15 秒按每 15 秒增加 1 张。没有分镜图、分镜图未生成成功或用户未确认，均不得进入视频 PROMPT、镜头级路由或视频生成。不能用文字分镜表替代分镜图。
> 九宫格用于在付费生视频前约束产品的样子与位置、人物关系、场景和构图，让用户快速建立成片预期并尽早修改；因此不能用“后面再看成片”替代。

1. 先用真实产品 PNG、实拍图或已确认的 P-HERO/P-PACKSHOT 合成 P2/P3 格；不要让图像模型凭空重画真实包装。纯人物/纯氛围/无产品视频仍必须制作分镜图，只是不触发产品保真检查。
2. 9 宫格只负责预演时间顺序、构图、产品位置、产品大小、人物关系和动作起点，不是最终高清产品资产。
3. 按资产触发矩阵判断是否需要 `KF-N`；需要时从对应 P2/P3 格和真实产品资产派生，单独检查产品轮廓、比例、主色、主要色块、手部遮挡、朝向；P3 还要逐项对照 Logo、文字、版式与 P-PACKSHOT。已豁免镜头直接使用对应分镜格与真实产品资产。
4. 用户确认整批宫格和被触发的关键帧后，才进入视频生成。批内失败只回炉对应资产，不逐张重新授权。
5. 视频生成时不要把整张 9 宫格作为唯一参考输入：氛围格用对应分镜格与人物/场景参考；P2 使用被触发的 KF-N + 产品参考，或经豁免确认的分镜格 + 真实产品参考；P3 使用真实产品资产微动/合成。
6. 15 秒或 30 秒的宫格是导演控制图，不等于一个 15/30 秒视频必须一次生成；最终按 Phase 7.5 路由和剪辑切点拆片。

### 九宫格分镜图生成 PROMPT 模板

宫格图由 AI 模型单次生成整张 3×3 图片，不做后期拼合。数据来源：Phase 7 分镜表 + 每格文字台账。每张宫格提交一个 PROMPT，填好即用。

**关键约束**：AI 模型在单张图内生成 9 个独立且不串内容的画格属于高难度任务，稳定性因模型而异。PROMPT 按下面格式写能让成功率最大化——核心是让模型理解"这是一张故事板网格图，不是一张全景图"。

```text
一张 3×3 故事板网格图，暗色背景。画面分为 3 行 × 3 列共 9 个等大矩形画格，格与格之间仅用 2 像素白色细线分隔，每个格子是独立的一帧电影静帧。顶部居中一行白色小字："[视频标题] ｜ 分镜预演 ｜ [时长] ｜ [SB-15/SB-30-A 等]"

第 1 行（左→右）：
- 第 1 格 00:00-00:02：[具体的画面描述——包括景别、场景环境、人物动作与表情、产品在画面中的位置与大小、光照氛围、镜头运动方向]，底部白色时间码"00:00"
- 第 2 格 00:02-00:04：[同格式，每格之间视觉上明显不同]
- 第 3 格 00:04-00:06：[同格式]

第 2 行（左→右）：
- 第 4 格 00:06-00:08：[同格式]
- 第 5 格 00:08-00:10：[同格式]
- 第 6 格 00:10-00:12：[同格式]

第 3 行（左→右）：
- 第 7 格 00:12-00:13：[同格式]
- 第 8 格 00:13-00:14：[同格式]
- 第 9 格 00:14-00:15：[同格式]

硬性要求：
- 全部 9 格必须使用同一种摄影风格、同一套色温与光照逻辑，但每格的构图、场景、人物姿态、产品朝向各有不同，视觉上必须能一眼区分。
- 产品在产品格（第[X]、[Y]、[Z] 格）中的外观形状、颜色、比例、朝向和画内位置与已确认产品资产图 [P-HERO / P-PACKSHOT] 100% 一致，不凭空画。
- 出场人物在所有格子中保持同一张脸、同一套服装、身高体型一致。
- 这是 9 个独立静帧的网格排列，不是一张全景图或拼贴画，严禁把不同场景的内容混合到同一个画格里。
```

**填充指引**：
- `[具体的画面描述]` 每条约 30-50 字（中文）或 20-40 词（英文），写镜头里**实际看到的东西**，不写"景别：中景""镜头运动：推"这类标签——直接写成画面："中景，厨房台面上[产品名]缓缓旋出，逆光透过水雾，镜头缓推近罐身标签"。
- `[X]` 处填实际的产品格编号（从 Phase 7 分镜表中 P2/P3 格的位置来）。
- P0/P1 氛围格用叙事描述即可；P2/P3 格额外强调与产品资产图的外观对账。

**生成后校验（纯整图模式）**：宫格图出来后，对照台账逐格检查。任何一格串景、串人物、产品变形、时间码与分镜不一致，**整张九宫格作废并按同一台账重跑整张**；不允许裁切、单格重生成后替换、拼合或局部修补。每张累计最多 3 次；仍失败则报告失败项与成本并暂停，等待用户调整台账或素材。

### 产品包装文字逐字写入规则

- **资产 PROMPT 必须写字**：只要产品包装文字、Logo、型号、配料表、酒精度或固定版式需要出现在资产图中，必须把客户已确认的包装原文逐字写进资产 PROMPT。
- **视频 PROMPT 必须写字**：只要镜头要求展示、读取或保留产品包装文字，必须把同一份已确认原文逐字写进该镜头视频 PROMPT；不能只写“参考产品图”“文字清晰”“保持包装一致”。
- **没有确认原文时**：不得猜写、不得从模糊截图臆补；标记“包装原文待客户提供”，该镜不得宣称文字保真。
- **逐字写入不等于渲染保证**：PROMPT 写入原文是模型约束和验收依据，不代表视频模型能正确生成文字；P3 文字/Logo/版式必须使用真实 P-PACKSHOT、实拍、微动或合成兜底。
- **发现乱码时**：Reference-locked 生成资产或对应视频镜头作废，按原文重跑；P3/Exact 则回到真实包装 PNG、实拍或合成链路。禁止涂抹伪造包装字或拿乱码交付；受控合成真实包装资产不属于“后期拼字”。

## P0-P3 产品可见级别

| 级别 | 含义 | 产品资产要求 | 可承诺范围 |
|---|---|---|---|
| P0 | 产品不出现或不可辨识 | 无；必须在审计总表标为 P0 | 不承诺产品展示 |
| P1 | 产品作为背景、远景或局部氛围出现 | 已确认 `P-CORE` 或同等真实产品参考，逐镜注明引用；不要求包装文字可读 | 不承诺远景中包装文字清晰，但不能换成概念产品 |
| P2 | 产品承担动作、近景展示或卖点 | `P-CORE + P-HERO`，每个 P2 镜逐镜重注入参考或登记获准复用来源 | 轮廓、比例、材质、主色和主要色块；不承诺文字/Logo 逐字保真 |
| P3 | 产品承担 Logo、包装文字、型号或转化信息 | `P-CORE + P-PACKSHOT`；如同镜含动作，再追加 `P-HERO` | 真实资产承担包装保真，禁止纯视频模型重画 |

### 逐镜产品资产审计总表（Phase 8 必交付）

完成触发矩阵判定后，必须额外输出一张“逐镜产品资产审计总表”。它不是资产清单的重复，而是用来证明每个镜头的产品级别、最低资产、实际引用与确认状态已经闭环。

| 镜号 | P级 | 路由等级 | 最低资产标准 | 实际资产 ID / 参考 | 状态 | 客户确认 | 豁免理由 / 回退动作 |
|---|---|---|---|---|---|---|---|
| M-N | P0/P1/P2/P3 | L1/L2/L3 | 按下表填写 | `P-CORE` / `P-HERO` / `P-PACKSHOT` / 无 | PASS / FAIL / 豁免 | 已确认 / 待确认 | 仅 P0 可豁免真实产品资产；其余写具体缺口与回 Phase 8 动作 |

**逐镜判定铁律：**
- `P0`：产品不出现，最低资产为“无”；必须在表中标明 `P0`，不得把实际出现的产品伪标为 P0。
- `P1`：最低为已确认的 `P-CORE` 或同等真实产品参考；不要求文字可读，但不得用概念产品、相似包装或纯文字描述代替。
- `P2`：最低为 `P-CORE + P-HERO`，每个 P2 镜必须写清本镜重新注入的 `P-HERO` 或获准复用的同场景真实参考。
- `P3`：最低为 `P-CORE + P-PACKSHOT`；若同时包含产品动作，则还需对应 `P-HERO`。Logo/文字/价格/版式必须由真实资产、微动或合成承载。
- 任一 P1/P2/P3 镜若最低资产未达标，状态只能为 `FAIL`，禁止用“后面补”“默认参考”或“资产完整”代替。

### 资产真实性等级

- **Exact**：客户实拍、透明 PNG、实拍视频或基于真实资产的合成；可承载 Logo、包装文字、型号和版式。
- **Reference-locked**：模型参考驱动或客户确认的 P-HERO；锁轮廓、比例、材质、主色和主要色块，不承诺小字/Logo 逐字准确。
- **Conceptual**：只允许用于分镜构图、节奏和叙事预演；不得作为产品资产、不得替代真实产品、不得进入正式电商视频的产品镜头。


| asset_id | 定义 | 真实性来源 | 允许用途 | 是否含可读文字 | 不可变项 | 客户确认 |
|---|---|---|---|---|---|---|
| `P-CORE` | 产品四视图总档案 | 客户实拍/官方物料 | 产品视觉 DNA、角度核对 | 是 | 轮廓、材质、主色、包装 | 必须 |
| `P-HERO` | 场景化产品保真首帧 | 真实产品图进入目标场景，或客户确认的保真合成图 | P2 单镜图生视频 | 视场景而定 | 正面比例、主要色块/图形 | 必须 |
| `P-PACKSHOT` | 正面透明 PNG/可抠图高清实拍 | 客户真实产品资产 | P3 微动、合成、信息镜 | 是 | Logo、文字、版式、型号 | 必须 |
| `P-TOP` | 罐顶/易拉环/开合近景 | 客户实拍 | 开罐/开盖/顶部结构镜 | 否 | 结构、材质、开合状态 | 触发镜必需 |
| `P-SIDE` | 侧面或手持可见面 | 客户实拍 | 侧拿、手持侧面、倒酒/倾倒镜 | 视情况 | 侧面图形、比例、材质 | 触发镜必需 |

**资产准备硬规则：**
- **所有产品级别都必须基于真实产品素材**：没有真实产品图就暂停正式电商视频流程，不允许用概念产品或相似包装顶替。
- L1：产品只在远景、背景或氛围里出现；仍使用真实产品参考，只是不要求包装文字可读。
- L2：至少 `P-CORE + P-HERO`；每个 P2 镜生成时重新注入同一真实产品参考。
- L3：必须额外具备 `P-PACKSHOT`；P3 镜中真实产品资产必须留在画面前景，不能让视频模型重画包装。
- 有文字、Logo、固定色块、型号等要求时，真实资产优先级高于任何文字提示词。

## 资产复用规则（多条视频之间）

- **人物黑白素描三视图（1×3 拼接单图）：跨视频共用**（可灵路径除外：选定可灵即免产素描，直接以授权真人照片/视频作 I2V 参考）。同一角色可共用同一张黑白素描三视图，只生成一次；共用的是角色结构参考，不代表真人脸部身份一致。
- **产品四视图（1×4 拼接单图）：跨视频共用**。同一 SKU 所有视频共用同一张四视图拼接单图，只生成一次，不重复生成。
- **其它资产（服装设定 / 场景锚点 / 道具 / 首尾帧）：每条视频独立，禁止跨视频复用**。服装按“角色 × 本条视频实际服装状态”管理：同一状态可跨镜复用，换装才新建；即使两条视频用「同类型场景」（比如都是办公室），也要各自重新生成不同变体，不沿用上一条的图。生成时每次产出新变体（文件名带视频编号或 `-v2`/`-v3`），不覆盖旧文件。
- **多品（多 SKU）**：每个 SKU 一张三视图拼接单图，互不混用。

## 产品四视图 / 人视三视图 制备规范（**两类都是 1×N 拼接单图**）

产品资产与人物黑白素描三视图是两类不同性质的资产：产品资产负责真实 SKU 外观保真；人物资产负责黑白素描形式下的角色结构、发型、服装和姿态参考（可灵路径除外：选定可灵即免产素描，直接以用户授权的真人照片/视频作 I2V 身份锚定）。**两类都按「一张图内 1×N 横排拼接」交付，绝不拆成多张独立图**。人物资产（非可灵路径）不得承诺最终随机视频对真人脸部 100% 还原；但若用户有权使用真人照片，可将其转换为黑白素描资产，或在可灵路径下直接作 I2V 参考。正式交付（非可灵路径）仍是黑白素描。

### 共通硬性规范

- **形态**：**1×N 横排拼接单图**（产品 1×4：正/背/侧/顶；人视 1×3：正/侧/背）。
- **画幅与风格**：产品四视图使用白底电商风；人物三视图使用白底黑白素描纸张风。两者均为 16:9 横版（产品因 4 角度稍密，可降至 16:9 更紧凑亦可），人物资产（非可灵路径）不得使用真人摄影或彩色肖像风格；可灵路径人物以授权真人照片/视频作 I2V 参考，不交付素描。
- **标注**：每个角度下方加一行小字标签（如「正视图」「后视图」「侧视图」「顶视图」或人视的「正面」「侧面」「背面」），标签字号一致、居中、颜色浅灰，**不喧宾夺主**。
- **不增量原则**：产品四视图就是 4 个角度（不上 6 视图、不上下双排）；人视三视图就是 3 个角度（不上四视图）。
- **生成方式分流**：产品四视图必须图生图，并以客户真实产品实拍图/透明 PNG 作为产品外观参考；人物三视图（非可灵路径）可文生黑白素描，也可在用户授权后把真人照片转为黑白素描。正式人物资产（非可灵路径）禁止输出真人照片；可灵路径选定即免素描，直接以授权真人照片/视频作 I2V 参考。
- **一致性 100%（PROMPT 强约束）**：PROMPT 必须写明实物/人物可见细节（产品轮廓/颜色/材质/Logo 方向/文字/型号/接口/开合状态；人物脸型/发型/体型/身高比例）与确认参考 100% 一致、不增删细节，让模型理解最高优先级。这是生成目标，不是效果保证；验收不通过仍按资产路由重做或改用真实资产。
- **缺角度处理**：参考图不全时，**先问客户**——「缺失的 X 视图，是补拍给我，还是用 AI 基于现有参考补全？」。客户选 AI 补的角度，必须在资产台账里标「待客户确认」，不得当作实拍看待。
- **验收**：整张图（包含全部拼接角度）一次性交客户确认，点头才进视频；标签、外缘、整体构图有任一不适，整图重做。

### 产品四视图（每 SKU 1 张，1×4 拼接）

- 拼接顺序：正视图 → 背视图 → 侧视图 → 顶视图（左→右）。
- 4 个角度平分画幅，每个角度下方有「正视图/后视图/侧视图/顶视图」小字标签。
- 比例：单罐单瓶类 4 角度充裕；复杂产品（多 SKU 套装）可改为 2×2 拼接，但仍是单图。

### 人物黑白素描三视图（每角色 1 张，1×3 拼接）

- 拼接顺序：正面 → 侧面 → 背面（左→右）。
- 3 个角度平分画幅，每个角度下方有「正面/侧面/背面」小字标签。
- 风格硬性锁定「黑白铅笔素描 / 黑白线稿」（人物资产非可灵路径唯一允许的视觉形式）；不允许把真人摄影、彩色肖像或写实真人三视图作为正式资产交付。可灵路径除外：选定可灵即免产素描，直接以授权真人照片/视频作 I2V 身份锚定。视频阶段是否还原真人风格必须由用户另行确认，不能反向改变人物资产图。
- 范围：以单人正面为主（脸部特写或全身均可，依角色设定需要），三视图用于表达外观结构、发型、服装与姿态；可直接作为可灵等模型的真人视频参考。
- 黑白素描人物参考可跨视频共用；虚构角色按视频需求独立生成。共用只表示角色结构参考一致，不表示真人身份复刻。

## 角色资产 = 黑白素描外观参考（**人物黑白素描三视图 1×3 拼接单图**）+ 服装设定（拆分）

角色资产拆成两件事，分别管理：

### 黑白素描人物参考（人物三视图 1×3 单图，表达「画什么样的角色」）

> 严格按上方「人物黑白素描三视图」规范生成（可灵路径除外：选定可灵即免产素描，直接以授权真人照片/视频作 I2V 参考）——一张单图内左→右为「正面 / 侧面 / 背面」，三角度并排、标签清晰、白底素描纸张风。这是本 SKILL（非可灵路径）唯一接受的人物资产形态；可灵路径以授权真人素材作 I2V 身份锚定；两类都不接受彩色肖像或写实真人三视图作为素描资产交付。

- 描述：年龄段、性别、脸型结构、发型发色、体型、身高关系；这些是素描中的角色设定，不是对真人身份的确认。
- **视觉硬锁**：黑白铅笔素描 / 黑白线稿，纸张纹理、石墨明暗、交叉排线；禁止真人摄影、彩色肖像、写实真人三视图、3D 人物、数字人、动漫/Q版。
- **参考图用途**：人物参考图如有提供且确认有权使用，可用于生成黑白素描资产并锁定用户要求的人物可见特征；输出仍须是黑白素描。进入视频生成时，素描本身或用户另行授权的真人素材均可作可灵等模型参考。
- **真人 IP**：非可灵路径也必须先交付黑白素描人物三视图；不得因为是真人 IP 而改成真人照片或彩色肖像。可灵路径下真人 IP 直接以授权真人照片/视频作 I2V 参考、免素描。
- **虚构角色**：每条视频独立生成黑白素描人物三视图。
- 不要把不同年龄/发型/结构设定塞进同一张图；衍生图一次只改一个条件（表情/姿势/机位）。
- 多人先分别生成各自的黑白素描三视图，再用身高/站位区分。

### 服装设定（锁定「穿什么」，每条视频变化）

- 上衣/下装/鞋/配饰、主辅色、材质
- **服装数量 = 出镜角色数 × 本条视频实际服装状态数**。同一角色在同一服装状态下可跨镜复用；剧情明确换装、时间跳跃或场景要求不同服装时才新增一套。
- **无论真人 IP 还是虚构角色，跨视频服装必须变化**，不沿用上一条视频的服装。
- 服装按脚本场景和角色行为来定：办公室穿正装、户外穿休闲、居家穿便服；同一视频不因“出现多个场景”而机械生成多套服装。
- 真人 IP 换装时，保留黑白素描中的角色结构、体型和发型设定，只换服装设定；不得转成真人照片或彩色人物图。

## 场景/产品/道具

电商短视频默认竖版 9:16 交付画幅（产品四视图资产例外，为白底 16:9），资产构图与分镜留白按此预留（横版仅当平台明确要求时）。

- 场景锚点写清：入口方向、窗户方向、主光方向、桌椅产品位置、镜头运动路径；跨镜保持轴线
- 场景按脚本逐镜盘点，出现几个场景就做几张，不同视频各自独立生成
- 产品四视图 1×4 拼接单图见上方「产品四视图 / 人视三视图 制备规范」，已有实拍图优先作参考输入，不重绘精确 Logo/包装文字/型号/成分表/认证
- 人物黑白素描三视图 1×3 拼接单图同上；生成阶段可直接使用素描，也可使用用户另行授权的真人参考，但不得把真人照片当正式人物资产交付
- 缺少真实产品图时暂停正式电商视频流程；仅当用户明确要求探索概念构图时，才可生成醒目标记为 `Conceptual / 非真实产品` 的占位图，且不得进入正式分镜确认、产品验收或出片

## 资产视觉指令集（PROMPT 结构）

> 所有资产图的 PROMPT 统一用「字段化指令集」：每类资产一段，用【】方头括号字段，逐字段写**可见、可测、可拍摄的物理细节**，禁止抽象审美词。每类末尾固定一段「生成要求」（摄影参数级，可直接复制去平台）。纯提示词模式下这段就是交付给用户的 PROMPT；生成模式下 agent 按此调生图。

### 全局禁用词（写任何资产 PROMPT 时一律替换）

| 禁用 | 换成 |
|---|---|
| 高级感 / 氛围感 / 大片感 / 质感拉满 / 电影级光影 / 杰作 | 可见物理细节（材质/光影/构图/明暗具体化） |
| masterpiece / best quality / cinematic lighting / movie poster | 同上，用中文物理描述 |

> **通用资产 PROMPT 总规则（GPT Image 2.0 等模型）**：所有资产严格按「资产类型 → 身份/用途 → 主体结构 → 关键视觉特征 → 状态与动作 → 空间/构图 → 光线与摄影 → 具体风格 → 一致性锁定 → 生成方式 → 交付形态 → 确认方式 → 禁止项」顺序输出。资产 PROMPT 只解决资产本身，不塞视频剧情、复杂表演、口播或整段时间轴。
>
> **具体化规则**：禁止单独使用“高级感、电影感、真实感、精致、可爱、素描风”等空泛词；必须改写为可见的结构、材质、比例、光线、透视、体积和物理关系。每个资产必须有独立 ID（如 `CHAR-01 / OUTFIT-01 / SCENE-01 / PROP-01 / P-HERO / KF-01`），参考图必须写明“仅定义什么”。
>
> **资产真实性等级**：`Exact`（真实 PNG/实拍/合成，可承载 Logo 与文字）；`Reference-locked`（锁轮廓、比例、主色与材质，不承诺模型逐字渲染文字，但只要文字需要出现，PROMPT 仍必须附已确认的包装原文）；`Conceptual`（只用于构图和氛围，不得标为真实 SKU）。

## 人物资产视觉边界

人物资产的最终交付形式固定为**黑白铅笔素描 / 黑白线稿**（可灵路径除外：选定可灵即免产素描，直接以授权真人照片/视频作 I2V 身份锚定），不是真人照片，也不是彩色肖像。用户授权的人物参考可用于生成素描；视频阶段可使用该素描，或另行授权的真人照片/视频作模型参考。是否使用真实人物风格必须按用户要求单独确认，不能反向改变人物资产图。

## 本地保存规范

```
assets/
  products/      product-<sku>-four-view.png（1×4 拼接单图）                ← 跨视频共用
  characters/    char-<id>-three-view.png（人物黑白素描 1×3 拼接单图）     ← 角色结构参考，可按项目复用
                 char-<id>-outfit-<scene>.png（服装设定，每条视频变体）
  scenes/        scene-01-office-anchor.png（每条视频独立，变体 -v2 -v3）
  props/         prop-01.png
  keyframes/     s03-first-frame.png
```

- 产品四视图 1×4 拼接单图放 `products/`，跨视频共用，只生成一次
- 人物黑白素描三视图 1×3 拼接单图放 `characters/`，按角色结构参考复用；不得标记为真人脸部身份资产
- 其它资产按视频各自生成新变体，文件名带视频编号或 `-v2`/`-v3`，不覆盖旧文件
- 文件名小写英文+数字+连字符。目标存在时创建 `-v2`、`-v3`，不覆盖

## 资产验收

- 产品四视图 1×4 拼接单图：轮廓/颜色/材质/Logo 方向/文字/开合状态与实物 100% 一致；**整图一次性交客户确认**，客户点头才进视频
- 人物黑白素描三视图 1×3 拼接单图：黑白媒介、三视图顺序、角色结构、发型、服装与姿态符合 SPEC；**整图一次性交客户确认**；不验真人脸部身份一致性
- 与产品相关资产（产品图、Logo、品牌名、店铺/包装相关）：严格确认，不自动放行
- 角色：黑白素描中的角色结构/发型/体型稳定；服装设定每条视频有变化且匹配场景风格；不得输出真人照片或彩色人物图
- 场景：空间布局/光源方向/时间/关键物位置连续
- 构图：符合画幅，主体完整，留出动作和字幕空间
- 安全：人物资产无真人照片、无可识别真人脸身份、无彩色肖像、无第三方水印、无随机品牌文字；产品资产按真实 SKU 资产规则验收
- 文件：能打开，路径存在，台账状态与实际一致

不合格时只针对一个失败点重生成，保留旧文件为版本。
